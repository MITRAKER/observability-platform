# Contributing

Thanks for helping! This guide gets you from clone to merged PR.

## Set up

```bash
git clone https://github.com/MITRAKER/observability-platform
cd observability-platform
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
pre-commit install          # runs the fast checks before every commit
docker compose up --build   # the whole stack
```

## Workflow

1. Open or pick an issue, then create a branch: `feat/short-name`, `fix/short-name`, `docs/...`.
2. Make the change, with tests. Keep PRs small: one idea per PR.
3. Write commits in the [Conventional Commits](https://www.conventionalcommits.org/) style:
   `feat: add ticket-severity burn-rate alert`, `fix(orders): handle empty body`.
4. Run the checks (pre-commit runs most of them for you):
   ```bash
   ruff check . && ruff format --check .
   mypy services/gateway/main.py services/orders/main.py services/payments/main.py \
        loadgen/loadgen.py alert-sink/sink.py tools/check_power_of_ten.py tests
   python tools/check_power_of_ten.py
   pytest --cov
   ```
5. Add a line to `CHANGELOG.md` under **Unreleased**.
6. Open a PR and fill in the template. CI must be green and a code owner must approve.

## Coding rules

The code follows the NASA/JPL "Power of Ten" rules adapted to Python. In
short: no recursion, every loop and every collection has an upper bound,
functions stay under 60 lines, every input is validated and every result is
checked, and there are zero warnings. The full table, with the reasons, is in
[LEARNING.md](LEARNING.md#the-nasajpl-power-of-ten).

If you must break a rule, add `# noqa: <code> (<reason>)` on that line. A
suppression without a reason will not pass review.

## Alerts and dashboards

- Every new alert needs a `promtool` unit test in `prometheus/tests/` and an
  entry in `docs/runbooks.md`.
- Dashboards are generated by `tools/gen_*_dashboard.py`. Edit the generator,
  then regenerate the JSON, so the diff stays reviewable.

## Releases

Maintainers tag `vX.Y.Z` following [Semantic Versioning](https://semver.org/).
The release workflow builds and publishes the images and creates the GitHub
release from `CHANGELOG.md`.

## Code of conduct

Be kind and assume good intent. This project follows the
[Contributor Covenant](https://www.contributor-covenant.org/version/2/1/code_of_conduct/).
